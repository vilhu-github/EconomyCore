# 0.1.5.4

## Major Changes

- Added support for Paper 26.3.
- All saving now runs on a single `TNE-Storage` thread. Autosaves no longer overlap or create new
  Craft Scheduler threads, and the server no longer waits 10 seconds for TNE when stopping.

## Fixes

- Fixed TNE failing to enable on Paper 26.3 (`NoSuchFieldError: MAP_COLOR`).
- Fixed decorated pot items failing to convert (`No conversion registered from String to Material`).
- Fixed balance changes being lost when plugins used Vault from several threads at once.
- Fixed `/tne reload`, `/tne reloaddb` and `Data.Sync.Reload` discarding balance changes that had
  not been saved yet.
- Fixed changes made during an autosave being skipped by later saves, and failed saves not being
  retried.
- Reloads (`/tne reload`, `/tne reloaddb`, `Data.Sync.Reload`) are now cancelled when unsaved
  balances cannot be saved, e.g. while the database is down, instead of wiping in-memory balances.
- One account or transaction receipt that fails to save no longer stops the others from saving.
- Fixed item currency balances of online players not being saved on shutdown.
- Fixed a failed YAML save blocking every later save of that account.
- Fixed `/transactions` showing nothing after a restart, payments missing from the recipient's
  history, and transactions made within the same second being merged into one entry. History now
  shows the newest transactions first, and the initiator shows the player or plugin (e.g. Vault)
  when there is no paying account.
- Receipt tables are updated automatically on MySQL and MariaDB so every participant of a
  transaction is stored.

Receipts saved before this version only kept their first participant; the missing details cannot
be recovered. Balances already lost to the bugs above need to be corrected manually.
